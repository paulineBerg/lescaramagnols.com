## Résultats par Catégorie

### 1. ✅ Requêtes Sûres (132/134)

#### A. Noms de tables/colonnes statiques (105 occurrences)
- **Pattern** : `sprintf('SELECT * FROM `%s`', $this->database->table('nom_table'))`
- **Exemples** :
  - `SqlLogStore.php:297` : `sprintf('SELECT COUNT(*) FROM `%s`', $this->database->table('log_entries'))`
  - `SqlNavigationStore.php:129` : `sprintf('DELETE FROM `%s` WHERE `set_id` = :set_id', ...)`
  - `CronJobRepository.php:86` : `sprintf('SELECT * FROM `%s` WHERE `code` = :code LIMIT 1', ...)`
- **Protection** : Noms de tables hardcodés dans le code
- **Verdict** : ✅ SÛR

#### B. Noms de tables depuis constantes (20 occurrences)
- **Pattern** : `$table` provient de `self::MODULE_TABLES[$module]` ou `self::DEFAULT_TABLES`
- **Fichiers concernés** :
  - `PrivateMigrationService.php` (4 occurrences dans fetchRows)
  - `PrivateBackupService.php` (16 occurrences)
- **Protection** : `MODULE_TABLES` et `DEFAULT_TABLES` sont des constantes statiques
- **Verdict** : ✅ SÛR

#### C. Requêtes avec échappement explicite (1 occurrence)
- **Fichier** : `export_admin_runtime_settings.php:98`
- **Code** : `quote_admin_runtime_identifier($database->table('cron_jobs'))`
- **Protection** : Fonction `quote_admin_runtime_identifier()` échappe avec backticks
- **Verdict** : ✅ SÛR

#### D. Requêtes DDL avec validation (50 occurrences)
- **Pattern** : `->exec(sprintf('ALTER TABLE `%s` ADD COLUMN %s', ...))`
- **Fichiers concernés** :
  - `PrivateApps/Documents/PrivateDocumentRepository.php` (2 occurrences)
  - `PrivateApps/RealEstateRental/Repository/RentalLifecycleRepository.php` (30 occurrences)
  - `PrivateApps/RealEstateRental/Repository/RentalUnitRepository.php` (5 occurrences)
  - `PrivateApps/RealEstateRental/AgencyManagement/Repository/AgencyImportRepository.php` (10 occurrences)
  - `PrivatePortal/Repository/PrivateUserRepository.php` (5 occurrences)
- **Protection** : Noms de colonnes validés avec regex ou listes blanchies
- **Verdict** : ✅ SÛR

#### E. Requêtes préparées (49 occurrences)
- **Pattern** : Utilisation de `prepare()` + `execute()` avec paramètres nommés
- **Fichiers concernés** :
  - `PrivateDataProtectionService.php` (40 occurrences dans safeSelect, safeUpdate, safeDelete)
  - `EditorialSchemaManager.php` (2 occurrences)
  - `DiscussionRepository.php` (9 occurrences)
- **Protection** : Séparation claire entre structure de requête et valeurs
- **Verdict** : ✅ SÛR

### 2. ⚠️ Risques Acceptables (2/134)

#### A. `PrivateBackupService::tableColumns()` et `uniqueIndexes()`
- **Fichier** : `backend/src/PrivatePortal/Operations/PrivateBackupService.php`
- **Lignes** : 859, 881
- **Code** :
  ```php
  $statement = $this->database->pdo()->query(sprintf('DESCRIBE `%s`', $this->database->table($table)));
  $statement = $this->database->pdo()->query(sprintf('SHOW INDEX FROM `%s` WHERE `Non_unique` = 0', $this->database->table($table)));
  ```
- **Source de `$table`** : Payload de backup (fichier JSON chargé)
- **Risque** : Un fichier de backup malveillant pourrait contenir un nom de table injecté
- **Mitigations actuelles** :
  - Code d'administration (non accessible publiquement)
  - Fichiers de backup contrôlés par les administrateurs
  - `$this->database->table()` ajoute un préfixe
- **Recommandation** : Ajouter une validation regex dans `validateBackupPayload()` :
  ```php
  if (!preg_match('/^[a-zA-Z0-9_]+$/', $table)) {
      return ['valid' => false, 'error' => 'invalid_table_name'];
  }
  ```
- **Verdict** : ⚠️ RISQUE THÉORIQUE (faible probabilité, impact élevé si exploité)
